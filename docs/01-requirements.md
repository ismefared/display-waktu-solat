## 1. Functional Requirements

## 2. UI/UX, Security & Non-Functional Requirements

| ID | Title | Description | Priority | Source | Acceptance Criteria |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **UI-001** | 10-Metre Viewing Readability | Design typography, contrast, and layout hierarchy specifically for ±10m viewing on 16:9 displays. | P0 (Critical) | Master Prompt §7, §8 | 1. Enforces 6-level information hierarchy (Level 1: Next Prayer & Countdown → Level 6: Events/Zikir).<br>2. High-contrast dark emerald/slate sanctuary palette (`>= 7:1` AAA contrast for primary numerals).<br>3. Tabular numerals (`tabular-nums`) on all clocks, countdowns, and timetables. |
| **UI-002** | Responsive Multi-Resolution Layout | Support 1920x1080 (primary), 1280x720, 4K, and desktop/tablet viewports without clipping or overflow. | P1 (High) | Master Prompt §9 | 1. Zero horizontal overflow across 1920x1080, 1280x720, and smaller viewports.<br>2. Clean single-elevation architectural surfaces. |
| **SEC-001** | Server Proxy & Secret Protection | Protect API integrations, validate external inputs, and sanitize all rendered content. | P0 (Critical) | Master Prompt §14 | 1. External APIs proxied via Express `/api/*` with timeout and schema validation.<br>2. No secrets exposed in client code.<br>3. WebRTC signalling validates room codes and message payloads. |
| **SEC-LAN-001** | Same-LAN Remote Control & Pairing Security | Enforce that mobile-to-TV pairing, remote control commands, and WebRTC streaming operate strictly when the mobile phone and display share the same local Wi-Fi/LAN network. Short-lived pairing sessions with explicit authorisation, expiry, revocation, and replay protection.<br>2. Reject unauthenticated, expired, revoked, or non-LAN remote control commands (fail closed).<br>3. Direct local WebRTC media transport only (`host` candidates); no public TURN relay fallback.<br>4. Verify deployment architecture compatibility before enabling remote control. |
| **NFR-001** | Offline & Failure Priority Degradation | Enforce 9-level priority hierarchy so lower-priority failures never break higher-priority features. | P0 (Critical) | Master Prompt §11, §12, §38 | 1. Cached prayer times in `localStorage` + server memory keep display functional offline.<br>2. Every external data panel shows `"Dikemas kini: HH:MM"` and explicit Stale/Offline indicators when threshold exceeded. |
| **NFR-002** | 24/7 Unattended Stability | Prevent memory leaks, timer drift, and infinite retry loops over weeks of continuous operation. | P0 (Critical) | Master Prompt §13, §39 | 1. Bounded exponential backoff on API retries.<br>2. Automatic midnight date rollover and next-day schedule prefetch.<br>3. Clean cleanup of intervals, WebSockets, and `RTCPeerConnection` instances. |
